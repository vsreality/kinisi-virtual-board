# v0.4 virtual IMU

SDK commands and IMU telemetry on a v0.4 board read a simulated Bosch BMI088. A unit at rest measures gravity on +Z, a repeatable unit-specific offset and filtered noise. Polling faster than 100 Hz can return exactly the same sample. The two dies update independently. v0.3 has no IMU.

## Firmware configuration

The v0.4 hardware profile selects one BMI088 on SPI2 with separate chip selects. Production `hw_imu.c` writes the following values and converts signed 16-bit samples into SI units. Register references are printed pages of the [Bosch BMI088 datasheet, revision 1.9, January 2024](https://www.bosch-sensortec.com/media/boschsensortec/downloads/datasheets/bst-bmi088-ds001.pdf).

| | Accelerometer | Gyroscope |
|---|---|---|
| Configuration | ACC_CONF 0xA8, ACC_RANGE 0x01 (pp. 29–30) | GYRO_BANDWIDTH 0x07, GYRO_RANGE 0x02 (p. 39) |
| ODR and −3 dB cutoff | 100 Hz, normal, 40 Hz (p. 16) | 100 Hz, 32 Hz (p. 39) |
| Range and SI per count | ±6 g, 6 × 9.80665 / 32768 m/s² | ±500 °/s, 500 × π / (180 × 32768) rad/s |
| Typical output noise density | XY 160 and Z 190 µg/√Hz | 0.014 (°/s)/√Hz |
| Modeled equivalent noise bandwidth | 62.832 Hz | 50.265 Hz |
| Modeled stationary RMS before quantization | XY 0.01244 and Z 0.01477 m/s² | 0.001732 rad/s |
| 25 °C offset scale | 20 mg | 1 °/s |
| Offset temperature coefficient scale | 0.2 mg/K | 0.015 (°/s)/K |
| Sensitivity temperature coefficient scale | 0.002 %/K | 0.03 %/K |

Bosch tables 4 and 5 (pp. 9–11) give typical characteristics. Accel noise is specified at ±3 g, 25 °C, nominal supplies, normal mode. The model applies it at ±6 g. Bosch lists 5460 LSB/g at ±6 g and 65.536 LSB/(°/s) at ±500 °/s. The simulator uses the exact firmware conversion, rounds to nearest count (ties toward positive infinity), and clamps to [−32768, +32767]. The datasheet gives typical gyro RMS of 0.1 °/s at 47 Hz. The simulation predicts 0.0993 °/s for its 32 Hz configuration from the density and assumed response.

## Physical assumptions

The input is specific force including gravity and angular rate at the board origin in chassis axes (+X forward, +Y left, +Z up). The level board installation rotates both vectors into native sensor axes (−X, −Y, +Z). Bosch defines package axes on p. 56. The board/chassis mounting is an installation assumption. A stationary bench starts at +9.80665 m/s² on Z.

Each die uses an equivalent continuous first-order low-pass with the specified cutoff. The simulator solves the step response exactly for piecewise-constant inputs. It uses one-sided white noise density times the square root of the filter's equivalent noise bandwidth (π × cutoff / 2). Sampled noise has exponential lag correlation from that same pole. This approximation includes noise above the output Nyquist frequency before sampling. The datasheet supplies a cutoff, and leaves the full signal/noise transfer functions and group delay undetermined.

Each seeded unit draws a fixed uniform signed offset, offset slope and fractional gain slope per axis. At a fixed temperature T, offset varies linearly with T − 25 °C and sensitivity is multiplied by 1 + slope × (T − 25 °C). The table scales define the synthetic population; they are neither characterized production distributions nor Gaussian standard deviations. The accelerometer offset is specified at ±6 g, 25 °C, nominal supplies. Its offset drift is listed as <0.2 mg/K. Gyro offset assumes nominal rails, 25 °C and cancellation off. Gyro sensitivity/offset thermal slopes are specified at ±2000 °/s across −40 to +85 °C and extrapolated to ±500 °/s. At 25 °C all units have nominal sensitivity. The model omits static scale spread, cross-axis errors, gyro g-sensitivity, nonlinearity, random walk, vibration, thermistor dynamics, rail variation and clock drift. It has no per-board calibration or measured silicon transfer function.

## Acquisition and delivery

Accel and gyro have separate sample identities, repeat periods of 10,000 µs and first events at 10,000 and 12,500 µs. The 2,500 µs relative phase is a reproducible simulation choice. The firmware configuration leaves synchronization disabled. Acquisition timestamps identify filtered output register updates; filter lag does not change the timestamps. The regular board exposes the latest registers after the 50 ms firmware settling interval. The development course additionally queues **each die** for 10 ms before delivery. On its 10 ms recording grid the observed ages are 10 ms for accel and 17.5 ms for gyro. The six-value GET_IMU wire response has no timestamp fields. Board time, source time, and record time have different uses.

The native executable and FirmwareBoard obtain motion from simulated motor shaft rates and configured wheel geometry under ideal no-slip contact. Without a configured chassis they simulate a stationary bench. The behavioral Python board uses its planar velocity state; development courses use an independent chassis driven by wheel travel and contact transmission. All include the rotating-body acceleration term. Explicit native `set_imu` samples, timestamps, status/fault fixtures and behavioral `set_imu` overrides bypass the noise and filters so fault tests can specify exact observations. Creating a fresh board restores automatic generation.

Default seed is 1, unit temperature 25 °C. Development courses save their sensor seed, configuration and timing with each run. Reproduce historical paired-clock recordings with their pinned simulator and firmware revisions. [Development collector](encoder-baseline.md)
